# Plan — #25 Add a LICENSE file to match `mod_license = MIT`

Ticket: [#25](https://github.com/maartenpeels/hytale_fpv_drone/issues/25) · chore

## What the ticket asks for

`gradle.properties` declares `mod_license = MIT` and `updatePluginManifest` copies that into the
generated `manifest.json`. There is no `LICENSE` file, so the declared licence has no text behind
it. Add the standard MIT text with the correct holder and year.

## Approach

One new file at the repo root: `LICENSE`, containing the unmodified OSI MIT text. No build change,
no code change, no test.

`gradle.properties` is **read-only** for this change. It is an ask-first path in CLAUDE.md, and
nothing here needs it edited — `mod_license = MIT` is already correct. The file is the thing that
was missing, not the declaration.

## The two judgment calls

**Copyright holder — `Maarten Peels`, not `MaartenPeels`.** `mod_author` is a packed
`name|email|url` triple whose name field is `MaartenPeels`, an identifier-shaped string for the
manifest. `git config user.name` gives `Maarten Peels`, which is what a human copyright line wants.
Same person; the spaced form is the correct one for a legal notice.

**Year — `2026`, single year, not a range.** First public commit and this change are both 2026, so
there is no earlier year to open a range with.

## Filename and placement

`LICENSE`, no extension, at the repo root — what GitHub's licence detector looks for, so the repo
sidebar will start showing "MIT" once this merges. `LICENSE.md` and `COPYING` are also detected but
`LICENSE` is the convention the ticket's phrasing assumes.

## Test strategy

None. There is no behaviour here: the file is not on any classpath, is not read by Gradle, and is
not bundled into the plugin jar by the `bundledCore` configuration. CLAUDE.md's rule that every
change lands with a unit test is scoped to physics, curves, crossing and race state — the things
that are impossible to verify by flying. A licence file has nothing to assert about.

Verification is therefore just `./gradlew build` proving nothing broke, plus reading the text
against the OSI original.

## Risks

Effectively none. The only way this change can be wrong is a wrong holder or year in the notice, or
a mistranscribed licence body — both checked by reading, both cheap to fix later.

## Out of scope — deliberately, and why

- **CLAUDE.md's "Known repo issues" entry** (`No LICENSE file, though mod_license = MIT`) becomes
  stale the moment this merges, and the ticket asks for it to be removed. It is **not** removed
  here: CLAUDE.md is being edited concurrently by another task in this wave, and two branches
  rewriting the same section is a guaranteed conflict for no gain. Flagged in the PR body so it is
  picked up rather than lost.
- **`README.md`** — also under concurrent edit in this wave. Untouched.
